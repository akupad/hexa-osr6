# 手动动轴 + 实时 3D，以及设备固件设置

这一页记录 2026-10-04 加的两块能力：一个是新页面「🕹 手动动轴」，一个是设置页里的「🧩 固件设置（进阶）」。
两块都是"直接把设备当成一台可控机器"来用，所以共用同一条安全纪律：**默认不动，用户明确开启后才动**。

---

## 一、🕹 手动动轴（`Views/ManualControlPage.xaml`）

### 它解决什么

想要一个"滑杆一推，机器就走到那个位置，右边 3D 同时跟着动"的界面 ——
不用先做脚本、不用开自动模式，也不用去校准窗里一个个按钮点。

### 界面

- **左栏（380px）**
  - 卡 1「🔒 先开开关，设备才会听你的」：`☑ 允许手动动轴`（**默认关**）+ 三行状态
    （设备 / 安全 / 现在在驱动设备的是谁）+「为什么不能动」一行 + 页面自带 `⛔ 立刻急停`。
  - 卡 2「六根轴」：`⟲ 全部归中` + 六行滑杆 0–9999（L0 行程 / L1 前后 / L2 左右 / R0 扭转 / R1 滚转 / R2 俯仰），
    每行右侧是当前值读数；0 = 一端、9999 = 另一端、5000 = 正中。
- **右栏**：`AxisPreview3D` 占满 —— **实时 3D 模型**，拖滑杆它就跟着动；下面一行小字是当前六轴原始值。
- 窗口宽度：≥900 并排、620–900 两栏等分、<620 上下堆叠（与游玩页同一套规则）。

### 安全设计（改这块之前先读）

| 要求 | 实现 |
|---|---|
| 默认不动 | `允许手动动轴` 默认不勾；不勾时滑杆是灰的，一根指令都不发 |
| 谁在驱动设备只有一个事实源 | 只用 `App.Engine.TryClaimDirectInput("manual")` / `ReleaseDirectInput("manual")`；"我在不在驱动"直接读 `DirectInputOwner`，**不另设标志位** |
| 不抢别人的控制权 | 拿不到就显示「现在由『X』在驱动设备：手动动轴让位，先去把它停掉」，**不 force 抢占** |
| 停手路径 | 取消勾选 / 页面不可见 / `Unloaded` / 急停 / 200ms 安全轮询（断线·急停·归中·输出被关·被别人接管）→ 停定时器 + 交还控制权 + 取消勾选 + 状态写「已停手」 |
| 不移回原位 | 停手就是"停在原地不动"，**不会**偷偷把轴移回中间（那会让用户以为机器自己跑了） |
| 下发节奏 | 50ms（≈20Hz）定时器节流，每帧六轴一次性 `TrySendDirectAxes(values, 0.12)`，走 `MotionSafetyLimiter` 限速 |

### 没做真机验证的部分

设备不在时只验了"页面能建、四档宽度不被切、默认不发指令"。
真机上要确认：拖滑杆机器是否平滑跟随、0.12s 插值手感、被别的控制源占用时的竞争表现。

## 一点五、〰 让它自己摆（正弦发生器）

同一页里的第二块能力：**不用手一直拖，让机器按一条正弦曲线一直摆**。

**长什么样**：卡片「〰 让它自己摆（正弦）」= 六根轴各一条「幅度」滑杆（0–100%，默认只给 L0 一个 40%）
+ 一条「速度」滑杆（0.05–2 次/秒，默认 0.5）+「▶ 开始摆动 / ■ 停止」+ 一行大白话说明。

**怎么动**：开始后按 **50ms 一帧**算 `值 = 50 + 幅度/2 × sin(2π×f×t + 相位)`（每根轴相位错开 1/6 周期，
六轴同时摆不会像机械那样整齐划一），六轴一次 `TrySendDirectAxes(values, 0.08)` 发出去，右边的 3D 跟着动。

**和「自动动作」的区别**：自动动作会按自己的规则**换花样**（一会儿快、一会儿换动作），
这个只摆你给的那条曲线、**不换**；适合安静地慢慢来，或者单独试某根轴的手感。

**安全**：跟手动拖动共用同一套闸门 —— 必须勾「允许手动动轴」才能开始（没勾/急停/断线/归中/被别人接管时按钮不可用并写明原因）；
六轴幅度全 0 时不许开始；控制权仍是同一个 `manual`（摆动与手动拖动互斥）；
取消勾选 / 离开页面 / 急停 / 安全轮询发现异常 → 立刻停摆并交还控制权，**不移回原位**。

## 二、🧩 固件设置（`Views/SettingsPage.xaml` 的「设备与排查」段）

### 设备的固件是什么

D0/D1 回 `SR6-Alpha4-ESP32.ino` / `TCode v0.3` —— 这是 **jcfain/TCodeESP32**（ESP32 版 TCode 固件，
SR6 可在它自己的网页里配）的自定义设备串。它支持一套**串口系统命令**：

| 命令 | 作用 |
|---|---|
| `#list-settings` | 打印这台固件支持的设置名 + 值类型（这就是能力探测） |
| `#setting:<名字>:<值>` | 改一项设置 |
| `$save` | 把设置写进设备 Flash（不改就断电丢） |
| `#restart` | 重启固件（串口断几秒，之后 Hexa 自动重连） |
| `#device-home` / `#motion-*` / `#pause` | **Hexa 一律不发**：这些会动设备或抢控制权，运动只能走引擎那条被限速器和急停管着的路 |

`#list-settings` 的输出长这样（源码 `SystemCommandHandler::formatCommand`）：

```
LeftServo_ZERO:<int>----------------------The zero calibration for the left servo
inverseStroke:<bool/bit>------------------Inverts the stroke direction
friendlyName:<string>---------------------The friendly name shown on the web ui
```

### 一个必须说清的协议限制

**串口读不到设备当前值**：固件只在它自己的网页接口里给值，串口协议只给了"列设置"和"改设置"。
所以 Hexa 界面里填的是**要改成多少**，不是现状 —— 卡片文案里写明了这一点，不假装读得到。

### 界面与用法

设置页 → 「设备与排查」→ `🧩 固件设置（进阶）`（**默认收起**，收起时右侧写状态：还没读设备 / 读到 N 项 · 未保存 M 项）：

1. **读取设置列表** —— 读不到就直说（可能不是 TCodeESP32 系、串口被占、或输出被急停锁着）；
2. 填要改的值 → **应用改动**（发 `#setting:名字:值`，还没进 Flash）；
3. **保存到设备**（`$save`，进 Flash，断电不丢）；
4. 提示"改完要重启"的项再点 **重启设备**（`#restart`，有确认框）。

常用项带中文名与默认值提示（SR6 上真正会用的那些），其余项按固件列出的原名 + 类型显示
（固件里有多少项就显示多少项，不写死）。

| 固件里的名字 | 中文名 | 默认 |
|---|---|---|
| `LeftServo_ZERO` / `RightServo_ZERO` | 左 / 右舵机零点（行程两臂） | 1500 · 改完要重启 |
| `LeftUpperServo_ZERO` / `RightUpperServo_ZERO` | 左上 / 右上舵机零点 | 1500 · 改完要重启 |
| `PitchLeftServo_ZERO` / `PitchRightServo_ZERO` | 俯仰左 / 右舵机零点 | 1500 · 改完要重启 |
| `TwistServo_ZERO` | 扭转舵机零点 | 1500 · 改完要重启 |
| `maxServoRange` | 舵机最大角度 | 180 |
| `inverseStroke` / `inversePitch` / `inverseTwist` | 反转 行程 / 俯仰 / 扭转 方向 | 0 |
| `continuousTwist` | 连续扭转 | 0 |
| `bluetoothEnabled` / `bleEnabled` | 蓝牙串口（SPP）/ BLE | 0 |
| `friendlyName` / `hostname` | 设备名 / 主机名（`<名字>.local`） | — |
| `vibTimeout` | 振动超时（毫秒） | 2000 |

### 版本差异（决定了这台机器能不能用）

- **v0.5b 及之后的 TCodeESP32 构建**有 `#list-settings` 与 `#setting`；
- 更老的构建（例如 `c0.371b`）只有 `#help` / `#restart` / `#wifi-ssid` / `#log-level` 这一小撮，没有 `#setting`；
- 界面上点一次「读取设置列表」就知道属于哪一类 —— 没回话就是不可用，此时可改走**固件自带的网页接口**（WiFi 那条路）。

### 代码在哪

- `Services/FirmwareSettingsService.cs`：解析 `#list-settings`、SR6 常用项的中文名/提示、值类型校验、常用项与其它项分组；
- `Services/SerialService.cs`：`IsAllowedFirmwareCommand`（白名单）、`SendFirmwareCommand`、`QueryFirmwareCommand`
  —— 后者的 I/O 走 `_ioLock`、**绝不占 `_lock`**（那要等 2 秒，占着那把锁会把急停堵住），调用方自己放后台线程；
- 单元测试 `tests/Hexa.CoreTests`：白名单放行 / 拒绝、命令注入拦截（含换行塞第二条）、解析、分组、值校验、空输入。
