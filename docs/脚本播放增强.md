# 脚本播放增强：多轴联动 / 空档填缝 / 脚本平滑 / 多轴命名

这几个功能都只影响**播放时的动作**，不改你的脚本文件。
默认值：**脚本平滑默认开**（用户 2026-10-04 要求，换向不硬折返、声音更小），多轴联动与空档填缝默认关。

入口：主界面 →「📚 脚本库」页，工具栏下面那张 **✨ 播放增强** 卡片。

---

## 1. 多轴联动

**解决什么问题**
社区 funscript 绝大多数只写了主轴 L0（上下推拉），其余 5 根轴整段停在中间 50。
设备于是只是一根"会上下的棒子"，快速段落和慢速段落摸起来没区别。

**怎么做的**
脚本**没写动作**的轴，按主轴的两种信号推出来：

| 轴 | 跟着什么 | 系数（相对联动幅度） |
|---|---|---|
| L1 推进 | 主轴速度 | 0.45 |
| L2 左右摆 | 主轴位置 | 0.85 |
| R0 扭转 | 主轴速度 | 1.00（最明显：动得快就扭转） |
| R1 左右倾 | 主轴位置 | 0.90 |
| R2 前后倾 | 主轴速度（慢档） | −0.70（与 R0 反相，做出"先冲后倾"的滞后感） |

- **脚本自己写了的轴，一个字节都不改**——那是作者的意图，改了就是篡改创作。
- 速度用 `tanh` + 一阶低通：不 tanh 的话一帧抖动就让扭转乱甩；不滤波会跟着 60fps 的采样噪声抖。
- 用**整条轨道的位置范围**归一化：脚本只在 45–55 之间小幅动时，其它轴不该甩出满行程。

**开关与幅度**
- 「多轴联动」勾选框 +「联动幅度」滑杆（5–60%，默认 30%）。
- 幅度 = 派生轴最多偏离中位多少（轴行程百分比）。
- 关掉「测试台 → 多轴动作」总开关时联动不生效（出口门控会把次要轴钉回中位），卡片里会写明原因。

## 2. 空档填缝

**解决什么问题**
很多脚本在间奏、对白、片头片尾有一段完全静止（位置一动不动好几秒）。
这时候设备死在那里，人会以为"是不是卡住了"。

**怎么做的**

- **空档的判定**：相邻两个动作之间，间隔 ≥「多长算空档」（默认 1.5 秒，可调 0.8–6 秒）
  **且两端位置差 ≤ 4** 的区间。位置差得多的区间是正常的慢动作，不是空档，不填。
- **填什么**：一条**慢正弦**（0.35–0.7 Hz，越响摆得略快），各轴相位错开——像设备自己在呼吸。
  幅度 = 「填缝幅度」（5–40%，默认 20%）× 当前响度。
- **只填作者没写动作的段落**，空档两端各有 250ms 淡入淡出，不会在边界蹦一下。
- **安静就静止**：响度低于门限时一帧都不改。声音停下后，相位冻结、幅度按 smoothstep 在 0.7 秒内收回保持位置——
  这样设备是"速度归零地停下来"，不会带着速度冲过保持位置再荡回来（实测过：不这样收尾会在空档里来回荡 ±17 个行程点）。
- 需要能听到声音：勾上时 Hexa 会自动开一条**只监听、不驱动设备**的音频通道
  （完整的"声音响应"会接管设备、和脚本播放互斥，所以不能用它）。

**实测**（模拟设备，脚本中段 3.2 秒静止）：

| 场景 | 结果 |
|---|---|
| 空档里有声音 | L0 被顶到 92–98（保持位置 80），多轴同时微动 |
| 声音停下后 | 精确回到 80.000，且**不再摆动**（三次运行：0.000 / 0.000 / 0.260） |
| 关掉填缝 | 保持段落 0.000 偏移（基线） |

## 3. 多轴脚本的两种命名

六轴脚本有两种文件命名约定，Hexa **两种都能读，也能都写出来**：

| 轴 | Hexa 约定 | 社区约定（MultiFunPlayer 等） |
|---|---|---|
| L0 | `名称.L0.funscript` | `名称.stroke.funscript` |
| L1 | `名称.L1.funscript` | `名称.surge.funscript` |
| L2 | `名称.L2.funscript` | `名称.sway.funscript` |
| R0 | `名称.R0.funscript` | `名称.twist.funscript` |
| R1 | `名称.R1.funscript` | `名称.roll.funscript` |
| R2 | `名称.R2.funscript` | `名称.pitch.funscript` |

- **导入**：选任意一个文件，同名伴生轴（两种命名都认）会一起进库；
  一个文件里带 `axes` 数组的"单文件多轴"脚本也照样读。
- **导出**：「脚本制作 → 微调波形 → 导出」，多轴时会问一句"是否同时导出一份社区通用命名副本"。
  选「是」就两种命名各写一份（内容完全相同），选「否」只写 Hexa 约定，和以前一样；
  已存在的文件只弹一次覆盖确认。

## 4. 脚本平滑

**解决什么问题**
动作点是「0ms 位置 20 → 200ms 位置 80」这样写出来的，播放器按直线插过去，
到点的一瞬间速度从 +300/秒 直接翻向。位移没错，**速度是断的**——机械听起来就是"嗒、嗒"。
补再密的帧也消不掉这个断点：它是曲线形状问题，不是帧率问题。

**怎么做的**
用**单调三次曲线**（Fritsch–Carlson / pchip）代替直线。三条硬性约束：

1. **单调**：两段之间只走它们之间，绝不冲过作者写的极值（普通三次样条会过冲＝设备跑到脚本没写的位置）；
2. **端点精确**：作者写的每一个动作点，曲线严格经过（实测误差 0.0000）；
3. **可调**：强度 0–100%，0% 逐点等于原来的直线插值。

**实测**（演示脚本，产品代码 10ms 采样）

| 指标 | 直线（现在） | 平滑后 |
|---|---|---|
| 动作点两侧速度差（最大） | 2000/秒 | 37/秒 |
| 经过动作点的位置误差 | 0 | 0.0000 |
| 是否冲过脚本写的极值 | 否 | 否（单调保证） |

**代价**：极短促的高频段落（比如每秒 8 下的抖动脚本）会柔化一点——这是取舍，不是 bug。
**开关**：脚本库页「✨ 播放增强」→「脚本平滑」+ 强度滑杆；**播放中直接拖动就能听出区别**
（切换带 0.35 秒过渡，不会跳位置）。

**结论与建议（实测后定的默认值）**

- 它的收益是**机械层面**的：拐角处不再要求"无限加速度"，换向更柔和、噪音与磨损更小；位移完全保真。
- 但**手感上差别很小**：因为安全限速器本来就在替设备磨拐角（速度/加速度/加加速度上限），
  而限速器顶不满的慢速段落，形状差别最多只有约 10% 行程。
- 代价是真实的：高频抖动段落会变柔——那是**改了作者写的东西**。
- 所以默认**关**：Hexa 默认完全按作者写的原样播放，想更柔的人自己开。
  建议开启的场合：高频抖动类脚本、手画波形导出的稀疏脚本、觉得换向"咔咔"响。

**自己对比的材料**：`demo/对比演示.html`（浏览器打开，有动画和强度滑杆）、
`demo/演示-原样.funscript` 与 `demo/演示-平滑后.funscript`（后者已经把平滑后的曲线写成脚本，
用任何播放器都能听出区别，不需要这个开关）。

## 5. 顺带修掉的一个老毛病（安全限速器自激振荡）

**症状**：脚本停住不动了，设备还在那儿来回荡。
**根因**：限速器原来在"离目标还远"时直接命令**全速**冲向目标，可剩下十几个点时从全速已经刹不住了
（沉浸档 360/秒、加速度上限 2400，刹停要 27 个点），于是冲过目标再往回追、追回来又冲过头。
**实测**：目标恒定不动时输出仍在 ±6 个行程点上来回；20 个点的阶跃冲过头 11.5 点、要 0.9 秒才停。
**修法**：命令速度改成"用剩下的距离还刹得住的速度"（对同一套物理模型二分反解），
其余逻辑（加速度/加加速度限幅、精确落点判断）完全不变。
**结果**：响应速度不变（700ms 内照样走到 99.3），余摆消失（安静后 0.000）。
所有限速器边界测试（速度上限、加速度上限、快动作响应）全部仍然通过。

## 相关设置（都在 `%LOCALAPPDATA%\Hexa\settings.json`）

| 键 | 默认 | 含义 |
|---|---|---|
| `ScriptAxisLinkEnabled` | false | 多轴联动开关 |
| `ScriptAxisLinkAmount` | 30 | 联动幅度（5–60） |
| `ScriptGapFillEnabled` | false | 空档填缝开关 |
| `ScriptGapFillMinMs` | 1500 | 多长算空档（800–6000） |
| `ScriptGapFillRange` | 20 | 填缝幅度（5–40） |
| `ScriptSmoothingEnabled` | **true** | 脚本平滑开关（默认开） |
| `ScriptSmoothingStrength` | 100 | 平滑强度（0–100） |
| `AudioListenOnly` | false | 只监听声音、不驱动设备（由填缝开关自动设置） |
