# 发布流程（tools\release.ps1）

## 为什么要有脚本

发布 Hexa 不是"编译一下"这么简单。手工发布要按固定顺序做八件事，其中任何一步漏掉都出过事：

| 曾经踩的坑 | 后果 |
|---|---|
| 直接 `dotnet publish` 到 `dist_hexa`，没先验证产物 | 有一版**没有原生 `onnxruntime.dll`**、`deps.json` 里 0 条 onnx 记录 → 画面识别在发布版里静默不可用 |
| 先 `rm -rf dist_hexa` 再发布，结果输出路径没解析成功 | 差点把唯一一份产物删掉（虚惊一场） |
| 把新产物当"暂存目录"跑了一次自检，它旁边没有 `presets.json` | 程序写出"只有内置动作"的新文件（32 条），换目录时差点把用户的 **42 条动作预设**覆盖掉 |

所以：**顺序固定、每一步都校验、失败就停**。

## 怎么用

```powershell
# 全流程：构建 → 单元测试 → 自检 → 发布 → 校验产物 → 换目录 → 校验最终目录
pwsh -File tools\release.ps1

# 只跑检查（不发布）：改完代码先看看有没有踩红
pwsh -File tools\release.ps1 -ChecksOnly

# 只发布（已经确认过代码没问题，省掉那几分钟）
pwsh -File tools\release.ps1 -SkipChecks
```

脚本位置：`Hexa/tools/release.ps1`（**故意只用 ASCII**：PowerShell 5.1 会把没有 BOM 的脚本按 ANSI/GBK 解码，
中文字面量会变成乱码并撑爆语法解析）。

## 它到底做了什么

1. **构建（Debug）** —— 要求退出码 0 且报告 0 警告。
2. **单元测试** —— `tests/Hexa.CoreTests`（纯逻辑，当前 239 例）。
3. **自检（Debug 构建）** —— `HEXA_SELFTEST` 跑一遍（当前 88 项），要求 0 项失败。
   自检自动把设置重定向到临时沙箱，**不碰你的真实设置**。
4. **发布** —— `dotnet publish -c Release -r win-x64 --self-contained true` 到
   `Hermes\_dist_hexa_new`（先清空这个暂存目录）。
5. **校验暂存产物** —— `Hexa.exe`/`Hexa.dll` 在、原生 `onnxruntime.dll` 在且 >15MB、
   `Hexa.deps.json` 里有 `Microsoft.ML.OnnxRuntime`。
6. **跑一遍"发布版自己的自检"** —— 这一步能抓到"Debug 能跑、Release 少了原生库"这类只在发布版出现的问题。
7. **保住用户数据** —— 把 `dist_hexa\presets.json`（exe 旁边的**动作预设，属于用户数据**）
   复制进暂存目录，并核对条数一致。
8. **换目录** —— 旧的 `dist_hexa` 整体改名成 `dist_hexa_prev_20260924`（可整份回滚），暂存目录改名成 `dist_hexa`。
   **绝不会在没确认新产物存在之前删掉旧目录**。
9. **校验最终目录** —— exe / onnxruntime / deps 记录 / presets 条数 / 文件数（>200）。

全部通过才打印 `RELEASE OK` 并以 0 退出；任何一步不过就列出问题清单并以 1 退出。

## 目录约定

```
_work\projects\Hermes\
├─ Hexa\                       源码（Hexa.csproj、Views、Services、docs、tests…）
│  └─ tools\release.ps1        发布脚本（本页说的这个）
├─ dist_hexa\                  当前发布版（桌面 Hexa.lnk 指向这里的 Hexa.exe）
│  ├─ presets.json             ← 用户数据！动作预设就在 exe 旁边
│  └─ onnxruntime.dll          原生推理库，画面识别靠它
└─ dist_hexa_prev_20260924\    上一版，整份留着，出问题直接换回来
```

## 回滚

```powershell
cd <仓库上级目录>
Rename-Item dist_hexa dist_hexa_broken
Rename-Item dist_hexa_prev_20260924 dist_hexa
```

（桌面快捷方式指向的是 `dist_hexa\Hexa.exe`，路径不变，所以换回来即可用。）

## 别忘了

- 发布**不包含**两个画面识别模型的权重（各 44MB / 13MB）：那要用户在界面里点「下载模型」。
- 发布前如果动过 `Hexa.csproj`（加/删 NuGet 包），务必看第 5 步的校验结果 —— 历史上出问题的两次都是这一类改动。
