## 一、窗口尺寸适配（最大化 / 小窗口 / 高 DPI）

### 1. 编排页：时间轴不再写死 200px，三块内容按比例分配

- **以前**：时间轴行固定 `Height="200"`；中间 3D 预览 `MinHeight="200"`、`TimelineHost`
  `MinHeight="150"`。1024×640 时预览会把时间轴压穿，最大化时时间轴又还是只有 200px。
- **现在**：三行改为 `Auto / 3* / 2*`，第一行 `MinHeight=180`、时间轴行 `MinHeight=150`；
  3D 预览 `MinHeight=180` 跟随卡片高度伸缩，`TimelineHost MinHeight=110`。
  动作库 / 段参数两列由 `220 / 260` 收窄为 `200 / 240`，给中间预览让出宽度。
  时间轴「复位」按钮由固定 `Width=44` 改为 `MinWidth=48`（“复位”两个中文字不再被硬裁）。
  动作库搜索框增加了占位提示「搜索动作名称/分类…」（空文本时显示，输入后隐藏）。
- **核实**：
  `Views/EditorPage.xaml:118`（外层纵向滚动兜底：`MinHeight` 绑 `ViewportHeight`）、
  `Views/EditorPage.xaml:121-122`（行高 `3*/2*` + MinHeight 160/132）、
  `Views/EditorPage.xaml:205`（`ComposePreview3D MinHeight=120`）、
  `Views/EditorPage.xaml:358`（`TimelineHost MinHeight=110`）、
  `Views/EditorPage.xaml:166-170`（列宽 200 / * / 240）、
  `Views/EditorPage.xaml:345`（复位按钮 `MinWidth=48`）、
  `Views/EditorPage.xaml:208-227`（搜索框 + 占位 TextBlock 的 DataTrigger）。
  改动前值见 `../../_layout_audit.md:12-20`（固定 200px、MinHeight 200/150）、

### 3. 设置页 / 测试台 / 游玩页：内容限宽并居中

- **以前**：内容直接铺满，宽屏（尤其 1920 最大化）下贴左，右侧留一大片空白。

### 4. 主窗口：最小尺寸收窄 + 启动时夹回工作区

- **以前**：`MainWindow.xaml` 为 `Width=1180 Height=760`、`MinWidth=940 MinHeight=640`，
  且没有按可用工作区修正；150% 缩放下 1920×1080 的逻辑工作区约 1280×680，窗口底部会被推到屏幕外，
  1366×768@150% 连最小尺寸都放不下。
- **现在**：XAML 最小尺寸改为 `MinWidth=880 MinHeight=560`；`MainWindow` 构造函数末尾在

  宽高各留 16px 余量，`Top/Left` 越界时分别夹回工作区。
- **核实**：`MainWindow.xaml:4-6`、`MainWindow.xaml.cs:67-75`（`Loaded` 里的 `WorkArea` 修正）。
  改动前值与「1280×680」的换算依据见 `../../_layout_audit.md:5`、`../../_layout_audit.md:29`。
- **说明**：`1280×680` 是 1920×1080 @150% 的 DIP 换算（并扣掉任务栏），不是代码里的常量；
  代码里真正读取的是运行时 `SystemParameters.WorkArea`。

### 5. 动作编辑器：初始高度与最小宽度

- **以前**：`Height=830`、`MinWidth=860`。830 DIP 在 150% 下约 1245 物理像素，1080 屏放不下；
  最小宽度小于底部一行控件（4 个滑块 + 4 个数值 + 标签）的需求宽度，数值会被裁。
- **现在**：`Height=760`、`MinWidth=900`，初始高度降低、最小宽度提高，底部一行能完整显示。
- **核实**：`Views/StrokeEditorWindow.xaml:4-5`；
  改动前值与实算见 `../../_layout_audit.md:42-47`、`../../_layout_audit.md:207`。

### 6. 全局按钮样式：收紧上下内边距，Height≤26 的按钮文字不再纵向溢出

- **以前**：`BtnBase` 的 `Padding="12,6"`；按钮内容区高度 = `Height - 12`，
  FontSize 11/12 的一行中文在 Height 22/24/26 时会被上下裁切。
- **现在**：`Padding="12,4"`，同样高度下多出 4px 内容区，高度 24/26 的小按钮文字能完整显示。
- **核实**：`App.xaml:465-470`（`BtnBase` 样式，`Padding` 在第 469 行）；
  改动前值、受影响按钮清单与实算见 `../../_layout_audit.md:44-48`。

### 7. 3D 预览：底部信息不再重叠，取景不再用外接球半径

- **底部信息**：左下实时数值与右下操作提示原来各自是独立 TextBlock，窄视口下会互相压。
  现在合并成一个两列 Grid（左列 `*`、右列 `Auto`），两块文字都加
  `TextTrimming="CharacterEllipsis"`，窄视口下各自省略而不是重叠。
- **取景**：原来用包围盒外接球半径估算相机距离，竖直方向偏大/偏小，最大化后模型会被裁掉一截
  或缩成一小团。现在改为「把包围盒 8 个角投影到相机的右 / 上 / 前三个基向量」，
  分别算出所需半宽、半高、半深，再取横竖两个方向所需距离的较大值 + 沿视线深度，最后留 6% 边距。
- **自动重新取景**：`SizeChanged` → `FrameCameraIfNeeded()`；首次一定取景，之后只有
  「视口宽或高变化超过 25% 且用户没有手动调过视角」才重新取景。
  用户一旦拖动视角（`_userAdjustedCamera = true`），窗口尺寸变化不再重置视角。
  `ResetView()` 会清掉手动标记并按**当前**视口强制重新取景，所以最大化/还原后点「重置视角」
  仍能把设备框满。
- **核实**：`Views/AxisPreview3D.xaml:78-98`（两列 Grid + `TextTrimming`）；
  `Views/AxisPreview3D.xaml.cs:125`（`SizeChanged`）、
  `Views/AxisPreview3D.xaml.cs:221-240`（首次取景、25% 阈值、手动视角保护）、
  `Views/AxisPreview3D.xaml.cs:242-320`（8 个角投影 + 基向量 + 距离计算；旧外接球问题见 265-270 行注释）、
  `Views/AxisPreview3D.xaml.cs:210-215`（`ResetView()` 强制按当前视口取景）、
  `Views/AxisPreview3D.xaml.cs:442` / `:484`（手动拖动 / `SetOrbit` 置位 `_userAdjustedCamera`）。
  底部重叠的改动前问题见 `../../_layout_audit.md:94-99`。

### 8. AI 助手页：顶部卡片封顶，状态文字不再被按钮挤掉

- **以前**：顶部卡片在 `Auto` 行，展开「角色卡」后把聊天区压到约 100px；

  `TextTrimming="CharacterEllipsis"`；右侧按钮组由 `StackPanel` 改为 `WrapPanel`，窄窗口自动换行。
- **核实**：`Views/AiAssistantPage.xaml:13-15`（`MaxHeight=360` + `ScrollViewer`）、
  `Views/AiAssistantPage.xaml:40-48`（两个状态 TextBlock 的 `TextTrimming`）、
  `Views/AiAssistantPage.xaml:65-99`（`WrapPanel`）。
  改动前问题见 `../../_layout_audit.md:126-144`。

## 二、脚本库播放链路（安全 + 闭环）

### 1. 急停会停掉播放器并把播放位置归零（Home() 解锁不会续驱设备）

- **以前**：`FunscriptPlayerService` 没有订阅 `Engine.StateChanged`，急停后播放时钟继续走；
  用户点「全部归中」解锁（`MotionEngine.Home()` 会清 `EmergencyStopped` 并重新使能输出）后，
  脚本会从急停那一刻的位置直接继续驱动设备。
- **现在**：构造函数订阅 `_engine.StateChanged`；`OnEngineStateChanged()` 发现
  `EmergencyStopped` 时切回 UI 线程执行 `StopForEmergency()`：暂停播放、停表、把
  `_positionMs` 归零，并且**不渲染归零帧**（避免急停瞬间再下发一帧）。
  其它引擎状态变化（规则引擎接管 / 自动任务抢占 / 断开连接）也会在播放中刷新页脚，
  让用户看到「为什么设备不动」。`Dispose()` 里退订 `StateChanged`，避免播放器被回收后仍被引擎唤醒。
- **核实**：`Services/FunscriptPlayerService.cs:53-60`（订阅与注释）、
  `Services/FunscriptPlayerService.cs:216-225`（`OnEngineStateChanged`）、
  `Services/FunscriptPlayerService.cs:234-242`（`StopForEmergency`）、
  `Services/FunscriptPlayerService.cs:244-249`（`Dispose` 退订）；
  `MotionEngine.Home()` 会解除急停的说明见 `Services/MotionEngine.cs:286-297`。
  改动前问题见 `../../_usability_review.md:17`。

### 2. 暂停 / 继续、停止与播放进度

- **现在**：脚本库工具栏新增 `⏸ 暂停` / `▶ 继续`（同一个按钮按 `IsPaused` 切文案）和
  `⏹ 停止`；页脚在有载入脚本时显示
  `播放中 mm:ss / 总长 mm:ss`（暂停时显示 `已暂停 …`，急停时显示
  `⛔ 已急停 · 已停止（播放位置已归零）`）。
  「停止」调用 `FunscriptPlayerService.Stop()`：暂停 + 停引擎输出 + 位置归零，且不渲染归零帧。
- **核实**：`Views/ScriptLibraryPage.xaml:32-37`（`PauseResumeBtn` / `StopBtn`）、
  `Views/ScriptLibraryPage.xaml:103-104`（`FooterText`）、
  `Views/ScriptLibraryPage.xaml.cs:121-159`（`RefreshStatus` 的进度 / 急停 / 拒绝原因）、

  `Services/FunscriptPlayerService.cs:111-126`（`Stop` / `Seek`）。
  改动前问题见 `../../_usability_review.md:15`。

### 3. 播放前判 `CanAcceptDirectInput`，接管时弹窗 + 页脚常显原因

- **以前**：`Play_Click` 只判 `CanRun`；声音响应 / 游戏伴随接管时，逐帧下发会被
  `TrySendDirectAxes` 静默拒绝，界面仍显示「播放中」而设备一动不动。
- **现在**：载入脚本后走 `TryStartPlayback()`，先 `StopAll()`，再判
  `App.Engine.CanAcceptDirectInput`（= `CanRun && !IsRunning && !RuleEngineActive`）。
  不满足就 `ShowPlayBlocked()`：弹窗写明原因；若 `RuleEngineActive` 还会提示
  「声音响应 / 游戏伴随正在接管，请先到「测试台」关闭后再播放」。
  失败原因同时写进 `_blockedReason`，页脚常显「⚠ 无法下发：…」；
  `FunscriptPlayerService.DirectInputBlockReason` 把急停 / 未连接 / 归中 / 规则引擎接管 / 引擎被占用
  分别映射成中文原因。
- **核实**：`Views/ScriptLibraryPage.xaml.cs:262-293`（`Play_Click`）、
  `Views/ScriptLibraryPage.xaml.cs:304-317`（`TryStartPlayback`）、
  `Views/ScriptLibraryPage.xaml.cs:318-328`（`ShowPlayBlocked`）、
  `Views/ScriptLibraryPage.xaml.cs:154-158`（页脚常显原因）、

## 三、其它实际使用改进

### 1. 设置页：已连接可断开；模拟设备有状态条和退出入口

- **断开连接**：`ConnectBtn` 不再永远是「立即连接」——`UpdateConnectButton()` 根据
  `_vm.IsConnected` 切成「断开连接」并换成 `BtnDanger`；`ConnectBtn_Click` 在已连接时
  调用 `App.Serial.Disconnect()`（同步关串口 + 关自动重连），并把按钮文案 / 状态刷新回来。
  模拟设备下 `Serial.IsOpen` 也是 true，所以按钮同样显示「断开连接」，点击会先退出模拟。
- **模拟设备状态条**：`SimulationBanner` 只在 `App.Serial.IsSimulation == true` 时显示，
  文案「当前是模拟设备（未连接真实硬件）· 点这里退出模拟」；点击调用
  `_vm.ExitSimulation()`（内部 `SetSimulationMode(false)` + 清 `settings.json` 里的 `SimulationMode`
  + 按需重连真机）。
- **没有把模拟开关加回来**：设置页 XAML / code-behind 里没有「模拟设备」复选框；
  `UpdatePortState()` 的注释明确写「『模拟设备』开关已按用户要求移除」。
- **核实**：`Views/SettingsPage.xaml:22-32`（`SimulationBanner`）、
  `Views/SettingsPage.xaml:70-72`（`ConnectBtn`）、
  `Views/SettingsPage.xaml.cs:479-486`（`UpdateConnectButton`）、
  `Views/SettingsPage.xaml.cs:490-503`（`UpdateSimulationBanner` / `ExitSimulation_Click`）、
  `Views/SettingsPage.xaml.cs:839-855`（`ConnectBtn_Click` 断开 / 退出模拟）、
  `ViewModels/SettingsViewModel.cs:149-167`（`ExitSimulation`）。
  改动前「没有断开连接按钮」见 `../../_usability_review.md:27`。

### 2. 托盘气泡：第一次隐藏提示一次；掉线 / 重连各提示一次

- **第一次隐藏到托盘**：`App` 在 `new MainWindow()` 后挂 `IsVisibleChanged`；第一次从可见变隐藏
  且不是退出流程时，`ShowBalloonTip` 一次「Hexa 仍在运行」+「窗口已最小化到托盘：双击图标恢复，
  右键「退出」才真正关闭。」，之后由 `_trayHideTipShown` 保证只提示一次。
- **设备掉线 / 重连**：`OnSerialConnectionChangedForBalloon()` 只在连接状态**真正翻转**时提示：
  断开时 `ShowBalloonTip`「设备已断开 · 正在自动重连…」（带上次端口名则显示「设备已断开（COMx）」），
  重连成功时「已连接设备 · 已连接 COMx」。启动时先记初始状态，所以启动阶段不会误报。
