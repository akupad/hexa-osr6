# 游戏桥「意图覆盖表」

> 为什么要有这张表：桥出过的三次真问题都不是"bug"，而是**游戏想表达的意图**与**位置舵机能做的事**不匹配
> （旋转→只能走到头；一直发同一个位置→被当成轨迹钉在端点；振动→本机没有对应物）。
> 这张表把「游戏能表达的每一种意图」逐条写清**桥现在怎么处置**，并由单测钉住一条铁律：
> **每种意图要么产生动作、要么明确回一条应答，绝不允许静默丢弃**（见 `tests/Hexa.CoreTests` 的
> `game bridge gives every intent a disposition (no silent drops)`）。

## 一、逐意图处置（对应 `Services/IntifaceBridgeService.cs` 的 `IntifaceProtocol.ProcessOne`）

| # | 游戏能表达的意图 | 桥现在的处置 | 由哪根轴承载 / 说明 |
|---|---|---|---|
| 1 | `RequestServerInfo` | 回 `ServerInfo{MessageVersion:3, ServerName, ServerMajor/Minor/BuildVersion}` | 握手，无动作 |
| 2 | `RequestDeviceList` | 回 `DeviceList`（six 模式：`Hexa OSR6 6-Axis`，6 个位置轴 + 3 个旋转轴；single 模式只有 L0+R0） | 见「呈现方式」设置 |
| 3 | `StartScanning` | 回 `Ok` + `DeviceAdded` +（v3 必须的）`ScanningFinished` | 走扫描流程的客户端不会卡住 |
| 4 | `StopScanning` | 回 `Ok` | — |
| 5 | `Ping` | 回 `Ok` | `MaxPingTime=0`（不要求客户端心跳） |
| 6 | `LinearCmd`（位置 + 时长） | **位置**：夹进轴限位 → 90ms 低通 + 舒适档限速（整形开启时）/ 原样透传（三个整形开关全关时）。**时长**：夹在 ≥60ms。six 模式按 `Vectors[].Index` 直接点名轴（0..5 → L0/L1/L2/R0/R1/R2），越界回 `Error` | L0/L1/L2（直线）+ R0/R1/R2（角度位置） |
| 7 | 同上、但**一直发同一个位置**（≥4 次） | **重新解释为"电平/油门"**：以该电平为中心做正弦往复（幅度 = 电平离中位的距离，周期 500–1200ms）；游戏给了新位置立刻退出；2 秒没有新指令就停 | 该轴自己（实测那款游戏 32 条全是 `Position 1.0`，原本会把 L0 钉在端点） |
| 8 | `RotateCmd`（速度 + 方向） | **位置舵机做不到"持续转"** ⇒ 重新解释为**往复摆动**：撞到限位就掉头，速度决定每秒走多少；`Index` 在 six 模式下点名 R0/R1/R2，越界回 `Error` | R0（扭转）/ R1 / R2 |
| 9 | `VibrateCmd`（强度） | 按设置四档：**关闭**（回 Ok、不下发、写一行"已忽略"说明）/ 照发 `V0`（本机无振动附件）/ **映射到旋转**（借用旋转状态机，全行程往复）/ **映射到小幅高频抽插**（幅度 5–20%、周期 300–700ms，最接近振动手感） | 小幅抽插走 L0；映射旋转走 R0 |
| 10 | `StopDeviceCmd` | single/six：全局 `DSTOP`；dual：只按住被点名那台设备的轴 | 停 = **状态**：同时清整形目标（`FreezeShaping`），否则"喊了停还会走最后一段" |
| 11 | `StopAllDevices` | 真的停（`DSTOP` + 清队列 + 清旋转 + 冻整形） | 以前落到 default 只回 `Ok`，"游戏喊停、机器不停" |
| 12 | 未知消息 | 回 `Error{ErrorCode:3}`（不再回 `Ok` 让客户端误以为"支持但不做"） | — |
| 13 | 设备掉线 / 恢复 | 主动广播 `DeviceRemoved` / `DeviceAdded` | 否则游戏一直以为设备还在、继续发指令 |

## 二、还没实现、属于"规范化缺口"的意图（明确记着，不假装支持）

| 意图 | 现状 | 真要做时的落点 |
|---|---|---|
| `ScalarCmd`（v3 唯一能说"持续往复/振动"的消息） | 未实现 → 回 `Error` | 按 `ActuatorType` 路由：Oscillate→持续往复、Vibrate→小幅高频 |
| `RawWriteCmd`（TCode 原生入口） | 未实现 → 回 `Error` | 规范要求默认不可见 + 用户 opt-in；`Osr6DeviceProfile.SanitizeTCode` 已有白名单 |
| `SensorReadCmd`（位置回读） | 未实现 | 可用 `MotionEngine.GetLastOutputSnapshot()` 回六轴位置 |

## 三、辅路（不进 Buttplug 协议，但同一台机器）

- **原始 TCode UDP**（默认关）：给 VAM / ToySerialController / CubiLink 这类只会发 TCode 的软件；
- **多输出**：把设备收到的 TCode 镜像到 `udp://` / `ws://` 目标（含 `DSTOP`）；
- **自有遥测桥**（UDP 26781）：游戏侧写一个适配器就能给出六轴 % + 语义字段，是"表达力最强"的那条路。

## 四、判据（回归时怎么验）

1. `dotnet run --project tests/Hexa.CoreTests` → 必须包含并通过 `every intent a disposition` 这条；
2. 真机跑一遍：`%LOCALAPPDATA%\Hexa\bridge-trace.log` 里每种意图都能看到 `RX` 原文与对应 `TX`（或 `!!` 说明行）；
3. 桥面板「最近指令」+ 侧栏状态行要能解释"为什么没动"（输出锁 / 急停 / 让位 / 等游戏连）。
