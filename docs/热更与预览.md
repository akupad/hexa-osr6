# 热更与预览

开发时改界面/逻辑代码，不用手动「关 Hexa → 编译 → 重开」；画面同步的预览区直接告诉你它在跟哪个窗口、抓到的是哪块画面。下面四块讲清用法和边界。

## 1. hot.ps1 怎么用

在仓库根目录（`Hexa.csproj` 所在那层）开 PowerShell：

```powershell
pwsh -File tools\hot.ps1              # 一直盯着：存盘 .cs/.xaml → 编译 → 重启
pwsh -File tools\hot.ps1 -Once        # 编译（并按需重启）一次就退出
pwsh -File tools\hot.ps1 -NoRun       # 只编译，不杀也不启动正在跑的窗口
pwsh -File tools\hot.ps1 -Debounce 1200   # 存盘后等 1200ms 再编译（连续保存收成一次）
# 只验证「能不能编译过」、不碰任何进程：
pwsh -NoLogo -File tools\hot.ps1 -Once -NoRun
```

- 编译通过：自动 `Stop-Process Hexa` 再拉起新进程，界面上就是「闪一下」。
- 编译失败：**完整输出写进 `%TEMP%\hexa-hot-build.log`**，控制台只打前 8 条带 `: error ` 的行；正在跑的那份 Hexa 不动，改坏代码也不会把能用的窗口搞没。
- `-NoRun` 单独用就是「只编译、不碰进程」，适合先把编译错误清干净再真机试。

为什么脚本不用你先手动关 Hexa：.NET 10 运行中的进程不会锁死自己的 exe / DLL 文件，`dotnet build` 能在窗口还开着时直接覆盖 `bin\Release` 里的产物；只是正在跑的那份还是旧代码，所以脚本在编译通过后再杀旧进程、起新进程，让新代码生效。手动关窗口省不掉这一步，只会多一次点鼠标。

## 2. 画面同步预览区显示什么

（预览区由另一个子代理在做，这里写它的目标形态。）

- **目标窗口**：当前「画面同步」在跟的窗口（进程名/窗口标题）。对不上、抓不到时会直接标出来，不假装在跟。
- **抓到的那块画面**：实际抓下来、缩到 160×90 后喂分析的那帧画面（`ScreenWatchService` 的 `FrameWidth×FrameHeight`，后面所有计算都在这张小图上做）。

用途是排障：姿态/场景「看不到东西」时，一眼分清是「根本没抓到画面（全黑/全白/窗口最小化/找不到窗口）」还是「图抓对了、只是判定没过线」。

## 3. 设置热加载何时生效

`App.xaml.cs` 里有个 `FileSystemWatcher` 盯住 `settings.json`（`StartSettingsWatcher`）：

- 从文件外面改完 `settings.json`，**存盘后约 0.6 秒**生效：600ms 防抖定时器把连续写盘收成一次，再 `ReloadInto` 原地覆盖 `App.Settings`。
- **Hexa 自己保存的 2 秒内不回声**：`QueueSettingsReload` 用 `AppSettings.LastSaveUtc` 判断，刚自己写出去的文件变动直接跳过，避免「界面拖滑条 → 存盘 → 读回 → 把拖动中的值顶回去」这种自激。

界面里改设置本来就即时生效，不需要等；这里补的是「用别的工具 / 手改文件」那条路。

## 4. 哪些设置必须重启才生效

热加载只做两件事：把磁盘值原地拷回 `App.Settings` + 专门处理「画面同步开关」。**在 `OnStartup` 里一次性启动/配置过的服务，热加载不会重新启动它**，所以这些改 `settings.json` 后要重启 Hexa：

- **界面语言 `UiLanguage`**：必须在 `MainWindow` 出现前定下来，否则首屏先按中文渲染一遍（`App.xaml.cs` 明确写这条）。
- **串口与连接**：模拟模式、启动自动连接、优先有线、串口号/备用串口 —— 只在启动时决定怎么连。
- **游戏遥测**：端口、令牌（`GameTelemetryService` 构造时按值传入）。
- **游戏桥 `GameBridgeEnabled`**：只在启动时 `Bridge.Start()`，热加载不会替你开/关。
- **Lovense 桥**：开关、端口、玩具名、行程百分比等（启动时一次性塞进 `LovenseBridgeService`）。
- **扇出 / 媒体库 / Web API**（`FanoutEnabled`、`LibraryWebEnabled`、`WebApiEnabled`）：都只在启动时 `Start()`。
- **合成 / 脚本目录**（`CompositionFolder`、`ScriptFolder`）：只在启动时套到静态仓库上。

画面同步这块特殊：

- **开关 `ScreenWatchEnabled` 是热加载专门处理的**：`App.xaml.cs` 里 reload 后当场 Start/Stop，改文件也能即开即关。
- 目标窗口、灵敏度、用不用姿态定位、场景门槛这些：`ScreenWatchService` 每帧直接读 `_cfg`，同步已经在跑时改文件即时生效。
- 但 **识别模型档位 `NsfwModelTier`** 和 **模型推理间隔 `ScreenWatchModelEveryMs`** 是 `ScreenWatchService` **构造函数里一次性取值**的（`NsfwClassifier.SetTier` 和 `_modelIntervalMs` 都在构造时算好），改这两项要重启才生效。
