# 自检与诊断（HEXA_SELFTEST）

## 为什么要有

这台机器**会真的动**，很多问题（例如"轴限位拖到最大、机器却不动"）只有把整条链路跑一遍才发现；
而单元测试碰不到界面、串口、桥、页面这些"只有跑起来才存在"的东西。

所以 Hexa 内置一个**全方位自检**：在**模拟设备**上把主要链路真跑一遍，输出一份人可读报告。
模拟模式下 `SerialService` 只把指令记进列表、**不写串口**，所以自检**不会驱动真实设备**。

## 怎么用

只有命令行一种入口（界面上不放按钮，避免日常使用被误触）。现在最省事的做法是走发布脚本，
它会把构建、单元测试、自检、发布、换目录、校验产物一次跑完：

```powershell
pwsh -File tools\release.ps1              # 构建 + 单测 + 自检 + 发布 + 校验产物
pwsh -File tools\release.ps1 -ChecksOnly  # 只跑构建 + 单测 + 自检，不发布
```

想单独跑自检：

```powershell
$env:HEXA_SELFTEST = "$env:TEMP\hexa-selftest.txt"
dotnet run --project Hexa.csproj -c Debug      # 或直接跑 Hexa.exe
```

跑完自动退出，报告写入指定路径。它会模拟触发一次急停与归中、约 30 秒内设备不响应，
**结束后自动还原你原来的设置**（只还原自检碰过的那几项：模拟模式、自动连接、游戏桥、声音响应、氛围叠加、游戏伴随、轴限位）。

**诊断运行绝不碰真实设置**：只要有 `HEXA_SELFTEST` 而没显式指定 `HEXA_SETTINGS_PATH`，
它就把设置重定向到 `%TEMP%\hexa-selftest\settings.json`（从真实设置复制一份，写也只写副本）。
这条是血的教训：早期自检把 L0 限位临时改成 3000–8000 却忘了还原，用户两次发现"L0 圆点不在两端"。

## 覆盖范围（88 项）

| 分组 | 检查内容 |
|---|---|
| 一、设备与安全 | 连接后可动、输出解锁、模拟模式生效；急停锁输出；**掉线重连不会清掉急停锁存**；「全部归中」后恢复可动 |
| 二、轴限位实时驱动 | 安全闸关闭时**一条指令都不发**；打开后**真的发出原始位置指令**（`L09999…`） |
| 三、脚本播放 / 四、播放增强 | 逐帧下发（1.5 秒 ≥20 条）；默认值（联动关、填缝关、**脚本平滑开**）与参数范围 |
| 五、氛围叠加 | 打开后会**开始监听声音**（曾因采集条件漏项变成"死开关"） |
| 六、游戏桥（Intiface） | 桥能启动；游戏指令经 WebSocket → TCode 真的落到设备；整形 / 舒适档限速默认开；桥驱动设备时全局状态认得出来 |

| 八、延迟标定 | 设备到位时间可算并给出合法补偿值 |

| 九点五、手动动轴页的正弦发生器 | 默认不摆、没勾允许时点不动；开始后按 50ms 一拍驱动、值都在 0–100，按停即停；窄窗下最宽控件 ≤420px |
| 九、界面冒烟 | 游玩 / 手动动轴 / 动作 / 脚本库 / 脚本制作 / 测试台 / 设置 / AI 助手 / 悬浮窗 / 校准窗 / 主窗口 逐个实例化，抓 XAML 解析与构造函数异常 |
| 十、界面与设置真的对得上 | 声音响应两种模式的联动、脚本库「多轴联动」控件与设置一致、游玩页控件不被拉满整行、游戏桥在游玩页且端口提示常显、测试台功能选择器两排三块、**设置页固件设置默认收起**、设置页宽窗两栏 / 窄窗一栏 |

## 写检查时的四条铁律（都是踩出来的）

1. **断言必须放在 `App.Dispatch` 外面**：写在投递的 lambda 里，界面线程一忙它就不执行，
   报告里既没有 ✔ 也没有 ✘ —— 比没有检查更糟。
2. **等条件而不是 Sleep**：固定 `Thread.Sleep` 会偶发假失败，用 `SpinWait.SpinUntil(条件, 超时)` 再断言。
3. **测"两个异步系统的握手"要允许重试**（伴随让位 ↔ 脚本播放就是这种）：真坏了会连续三次都失败，
   判别力不变，调度抖动被吸收。
4. **失败时先在报告里打现场**：写一行"现场：谁在驱动设备 / 是否急停 / 串口状态 / 关键标志"。
   这一行比十句猜测都值 —— 例如"脚本放不出来"最后查出来是**上一节留下的急停锁存**（见下）。

## 已知的两个坑

- **前后节互相污染**：前面几节会故意急停 / 断线（那些是安全项要验），掉线看门狗可能把急停锁存留到后面。
  需要"设备能动"这一前提的检查先调 `EnsureEngineRunnable()`（内部走 `Engine.Home()` 解锁 + 等 `CanRun`），
  报告里会留一行「清掉了上一节遗留的急停锁存」。
- **折叠面板（`Visibility=Collapsed`）的子树不参与布局、不在可视树里**：`FindByName(page, "内部控件")` 会返回 null。
  正确做法是拿到面板实例、用它自己的名字域查（`host.FindName("BridgePortBox")`），或者先让它可见再查。

## 它抓到过什么（真实案例）

- 「轴限位拖到最大机器不动」：限位驱动被界面安全闸挡住；
- 「脚本播放中侧栏却写待机」：脚本没有置"在动"标志 → 悬浮窗急停被禁用；
- 「声音响应勾了没反应」：采集条件漏项，成了死开关；
- 「L0 圆点不在最大最小」：自检写脏了用户真实设置；
- 「点快切换页面就闪退」：设置页在 `IsVisibleChanged`（布局过程中）弹模态框，抛
  `InvalidOperationException：调度程序处理已暂停` —— 现在既拆掉了对话框，也加了定向兜底与回归断言；
- 「游玩页要滚三屏」：游戏桥整卡常显 → 改成一行折叠 + 状态摘要，整页 2300px → 854px。
