## 一、还差的测试（最高优先）

| # | 要测什么 | 为什么重要 | 怎么构造 |
|---|---|---|---|
| 1 | **串口写失败 → 锁输出 → 恢复** | 实测真实发生过（`信号灯超时时间已到 'COM3'` × 59 次）。写入失败会锁输出并关端口；重连成功后引擎会自动重新使能输出，但这条恢复链路**没有任何自动化测试** | 做一个会抛 `IOException` 的 `ICommandTransport` 桩，`OutputEnabled = true` 后调 `Send`；断言：`OutputEnabled == false`、`LastError` 非空、`UserAdvice` 在连续失败 ≥3 次后出现；再让桩恢复后断言能重新解锁 |

## 二、已知问题（按严重度）

### ① 遥测没有限速，且每个包都做一次前台进程查询
- 位置：`Services/GameTelemetryService.cs`（收包循环）＋ `Services/RuleEngine.cs`（每包解析前台窗口/进程名）。
- 影响：本机任意进程高频发包就能把唯一的收包循环拖垮 → 内核缓冲溢出 → **静默丢帧**（界面只显示“游戏遥测”，看不出丢）。
- 建议改法：收包循环改成“取最新包覆盖 + 计数丢弃”，或把前台进程名结果按 ≤250ms 缓存；再给每个来源端点加一个包/秒配额。

### ② 遥测端口绑定失败在界面上不可见
- 位置：`Services/GameTelemetryService.cs`（绑定失败只写日志、`Listening=false`）＋ 界面只显示配置端口。
- 建议改法：把 `Listening / Port / LastError` 暴露到设置页与规则卡片；绑不上时红字提示并建议换端口。

### ③ 游戏桥的 trace 日志仍在实时线程上做同步文件写
- 位置：`Services/IntifaceBridgeService.cs`（每条 RX/TX 一次 `File.AppendAllText`，含 4MB 轮转；调用点在收包线程与 50ms 节拍线程上。实测同一毫秒内出现 6 条 TX = 6 次追加 + 每次 `Directory.CreateDirectory`）。
- 另外：轮转时 `File.Move` 若被占用，之后**日志会永久写不进去**（只警告一次）。
- 建议改法：改成后台单消费者队列 + 常开 `FileStream`；轮转失败降级为“截断续写”而不是整条不再记录。

### ④ `IsArmed` / `Disarm()` 是死代码
- 位置：`Services/MotionEngine.cs`。`IsArmed` 声明即为 true、只被赋 true；`Disarm()` 是空实现；`CanRun` 也不看它。
- 建议改法：删掉这两个成员，或让 `Disarm()` 真的锁住输出（需要一个明确的产品语义再动）。

### ⑤ 自检里那条“抓画面”检查依赖环境（已做优雅降级，仍有残余）
- 位置：`Diagnostics/SelfTest.cs`。它抓的是自己的窗口；窗口最小化/无内容时会是 0 帧。现在**只有明确的抓取错误才算失败**，0 帧写成“已跳过＋原因”。
- 残余：如果窗口可见但抓取接口本身被系统拒绝（少见），仍可能报失败 —— 遇到时按环境问题处理，不要当回归。

## 三、怎么跑这套验证

```powershell
dotnet build Hexa.csproj -c Debug                 # 应 0 错误 0 警告
dotnet run --project tests/Hexa.CoreTests          # 单元测试（262 项）
$env:HEXA_SELFTEST="$env:TEMP\hexa-selftest.txt"  # 界面级自检（97 项）
dotnet run --project Hexa.csproj -c Debug
./tools/release.ps1                                # 构建 → 单测 → 自检 → 打包 → 校验
```

> 注意：`tools/release.ps1` 的“0 警告”闸门对**联网产生的警告**很敏感（例如 NuGet 取不到漏洞库会报 NU1900）。
> 项目已在 `Hexa.csproj` 里关闭 `NuGetAudit` 以保证离线构建安静；如果你的环境仍报警告，请把它当成构建环境问题，而不是代码回归。
