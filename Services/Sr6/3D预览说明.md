> **状态：已完成**（2026-09-09）。`AxisPreview3D` 现在渲染的就是 osr-emu 那台带完整逆运动学的真 SR6，
> 六轴各自驱动真实机构，不再是示意用的方块机器人。

## 关键结论（踩过的坑）

1. **朝向**：模型原生坐标是 **Z 轴向上**（底座 z≈0、接收器 z≈212mm、连杆沿 +Z 伸向接收器）。
   osr-emu 官网那套「整组绕 X 轴转 −90° + `camera.up=(0,0,1)`」实测会把机器摆成侧躺；
   本预览用**原生坐标 + 相机 UpDirection=(0,0,1)**，`HelixViewport3D.ModelUpDirection="0,0,1"`。
   注意 `LookDirection` 是相机看出去的方向、相机位于 `center − direction×distance`，
   想让相机在上方，direction 的 Z 分量必须为负。
2. **材质 = 纯色漫反射**：`Sr6Rig.MakeMaterial` 只返回 `DiffuseMaterial`（冻结后共享）。
   **既不加 `EmissiveMaterial`（自发光），也不加 `SpecularMaterial`（高光）**——
   自发光给表面加一层与光照无关的恒定颜色、像蒙了光膜；高光在大面积平面上泛白、糊掉明暗关系。
   两条都是用户反馈后定下来的。osr-emu 原色（#1E1E1E / #131313）在深色 UI 背景上会糊成一片，
   已整体提亮漫反射色。
3. **scale 传 1**：轴值已经包含振幅，再乘一次 ayva 的 scale 会把中位偏移掉，所以 `Sr6Rig.Update` 的
   scale 恒为 1，振幅只用来缩放地面指示环。
4. **性能**：**53,143 个三角形**（实例化后统计，`tests/Hexa.CoreTests` 里从
   `MeshGeometry3D.TriangleIndices` 现算）；运动学单次更新约 **0.03ms**（内置 120ms 刷一次，可忽略）；
   首次解析 OBJ 约 **70ms**，之后实例化 **0ms**（几何冻结且跨预览控件共享），
   每帧只写 `MatrixTransform3D.Matrix`。
5. **验证**：`tests/Hexa.CoreTests` 现有 **128 项，全绿**。其中黄金数据回归用 node 跑官方 JS 实现
   生成 10 组轴值 × 25 个部件的局部位置 + 四元数，逐部件比对：
   **位置误差 ≤0.0012mm、旋转误差 ≤5e-8**。

## 交互：左键拖动 = 相机绕设备中心自由旋转

> ⚠ **本节已按 2026-09-09 晚的代码更正**。本页上一版写的是「左键拖动转的是设备本身
> （偏航绕世界 Z 轴、俯仰限幅 ±75°、写模型根节点 `MatrixTransform3D`）」——那套实现
> **已经不在** `Views/AxisPreview3D.xaml.cs` 里。当前代码（第 41–43、354–474 行）转的是
> **相机**：设备本身不动，动的是相机的位置偏移与上方向。

- **左键拖动 = 相机绕设备包围盒中心（`_orbitTarget`）自由旋转**，360° 无上下限位、不夹取角度：
  偏航绕当前屏幕竖直轴、俯仰绕当前屏幕右向量（都由 `camera.LookDirection` / `UpDirection`
  现算），`OrbitYawPerPixel = 0.42°/px`、`OrbitPitchPerPixel = 0.32°/px`。
- **Shift+左键 / 中键拖动 = 平移**（`PanGesture="Shift+LeftClick"`、`PanGesture2="MiddleClick"`）。
- **滚轮 = 缩放**（另有 `Ctrl+右键` 拖动缩放）。
- **中键双击**或点右下角「重置视角」= 相机回默认机位
  （`ResetView()`：`_orbitRotation = Identity` + `CameraController.ResetCamera()`）。
- 首次布局完成时按模型包围盒自动取景一次（`FrameCameraIfNeeded`），同时记录
  `_orbitTarget` / `_orbitBaseOffset` / `_orbitBaseUp`；之后改窗口大小不再重置用户转过的视角。

实现关键：相机旋转已经关掉（`IsRotationEnabled="False"`），左键不再交给 `CameraController` 做旋转，
改由 `AxisPreview3D` 自己处理鼠标拖动；`CameraController.CameraTarget` 仍钉在设备包围盒中心，
只作为平移与「重置视角」的参考点。

> **界面文案与代码不一致（待清理）**：`AxisPreview3D.xaml` 右下角提示仍写着「左键拖动转动设备」、
> `AxisPreview3D.xaml.cs` 构造函数里的注释仍写「左键拖动 = 转动设备」，这两处是上一版遗留文案，
> **以本节描述（转相机）为准**。改 UI 文案属于 .xaml 改动，本轮文档更新不动它。

## 视角旋转的增量实现（本轮 2026-09-09 晚）

拖动旋转现在**按增量旋转当前相机**，而不是把累计旋转套回固定基准机位：

- 鼠标移动时 `OnViewMouseMove` 用当前帧的 `dx`/`dy` 算出增量四元数 `delta`，累加进
  `_orbitRotation`，然后调 **`ApplyOrbitDelta(delta)`**：把「相机当前位置 − `_orbitTarget`」
  与 `camera.UpDirection` 一起按 `delta` 旋转，写回 `camera.Position` / `LookDirection` / `UpDirection`。
- 因此**滚轮缩放、Shift+左键 / 中键平移之后的距离与位置，不会被下一次拖动弹回默认**——
  增量作用在「当前相机」上，HelixToolkit 的滚轮 / 平移直接改相机也能被保留下来。
- `SetOrbit(yaw, pitch)` 与复位仍走**绝对机位**：`SetOrbit` 基于 `_orbitBaseOffset` /
  `_orbitBaseUp` 重算 `_orbitRotation` 后调 `ApplyOrbit()`；
  `ResetView()` 则是 `_orbitRotation = Identity` + `CameraController.ResetCamera()`
  （回到 `DefaultCamera` 的默认机位，它**不**走 `ApplyOrbit`）。
- 背景：上一版每次拖动都把「默认机位偏移 × 累计旋转」整体套回相机（`ApplyOrbit` 的绝对做法），
  于是用户先滚轮拉近、再拖动时，距离会被一次性拉回默认值。

## 光照与材质（踩过的坑）

- **机器本体材质 = 纯色 `DiffuseMaterial`**（`Sr6Rig.MakeMaterial`），
  **禁止 `EmissiveMaterial`（自发光）、禁止 `SpecularMaterial`（高光）**：
  自发光会加一层与光照无关的恒定颜色，整台机器像蒙了一层光膜、泛白，明暗关系变平；
  高光在大面积平面上泛白、糊掉明暗关系（两者都收到过用户反馈）。
  深色件在深色背景上的可读性靠提亮漫反射色 + 压低环境光解决。
- **灯光只有三盏**：环境光 `0x444E5A` + 主光（`DirectionalLight 0xF0F6FF`）+ 弱补光
  （`DirectionalLight 0x3C4856`）。灯越多、环境光越亮，画面越平。
- 例外只有两处 **UI 指示，不是设备表面**：地面振幅指示环与轴高亮材质仍用
  `EmissiveMaterial` / `SpecularMaterial` 做发光提示——
  振幅环 = `DiffuseMaterial 0x66·#17B890` + `EmissiveMaterial 0x28·#0F7A5F`；
  轴高亮 = `DiffuseMaterial #2BFFB8` + `EmissiveMaterial #12664A` + `SpecularMaterial #9FFFE2`（power 45）。

## 宿主页面的实时预览（动作页 / 编排页）

`AxisPreview3D` 内置一个 120ms 的 `DispatcherTimer` 读引擎实时输出（`RefreshPreview`）。
宿主页面要自己控制数据源时，统一用公开属性 **`AutoRefreshEnabled`** 停掉内置刷新，再由页面按帧喂
`UpdateAxes`；两个页面都是这个用法：

- **动作页 `StrokesPage`**：鼠标悬停动作卡片 → **右侧 3D 主预览直接试看该动作**——
  60 BPM（1 圈/秒）本地采样 `MotionEngine.SampleTempestAxis`，40ms 一帧，只做可视化、**不碰设备**；
  鼠标离开（延迟 150ms 恢复，避免卡片之间移动时闪）、开始播放、归中时恢复引擎实时输出。
  原先的独立悬停弹窗 **`StrokePreviewPopup` 已删除**，不再有「悬停弹小窗」这条路。
- **编排页 `EditorPage`**：`ComposePreview3D.AutoRefreshEnabled = false`，由页面按帧喂 `UpdateAxes`。
  否则控件内置的 120ms 引擎刷新会和编排预览两路数据打架，预览里的动作会闪（用户反馈）。
  切到微调页（`MainTabs.SelectedIndex != 0`）时恢复 `AutoRefreshEnabled = true`，交还给控件自己刷。

## 对外契约（勿改）

`AxisPreview3D` 的 `UpdateAxes / UpdateAmp / RefreshPreview / HighlightAxis / HighlightedAxis /
ResetView / AxisValues / AmpValues / AxisOrder`，以及公开属性 **`AutoRefreshEnabled`**
（`false` = 停掉内置的 120ms 刷新，宿主自己按帧喂数据），还有名为 `_timer` 的 120ms
`DispatcherTimer` 字段。早期版本里 `StrokePreviewPopup` 靠反射去拿 `_timer` 停刷新，
弹窗删掉后这条路已经没有了，宿主一律走 `AutoRefreshEnabled`。

轴高亮映射见 `Sr6Rig.BuildAxisHighlightMap()`（查询用 `Sr6Rig.MeshesForAxis()`）：
L0 接收器 / L1 四根主臂 / L2 四根连杆 / R0 机头外壳 / R1 左右俯仰臂 / R2 俯仰连杆 + 前轴承。

## 相关：拖动限位时的实时下发（设置页轴限位）

不是 3D 预览本身，但和「拖动 → 设备」是同一条链路，记在一起。**注意：本轮已加安全闸**——
设置页六轴限位滑块（`SettingsPage` 的 `RangeSlider`）拖动时是否真的下发，取决于
**「拖动限位时实时驱动设备」复选框**（`LiveLimitDriveCheck` → `AppSettings.LimitSliderDriveDevice`，
**默认关**、勾选状态持久化）：未勾选时 `DriveAxisFromSlider` 直接 return，拖动只改限位数值、
绝不发串口指令；同时 `RangeSlider.IsWheelAdjustEnabled = false`，鼠标滚轮扫过滑块不再改值
（事件不标记 `Handled`，正常滚页面）。勾选后拖动才**立即下发**，并做 **90ms 限流**（避免刷屏）；
另外**停手 140ms 后尾随补发最后一次值**——最后一次变更很可能正好落在 90ms 限流窗口里被丢掉，
于是出现「拖到最大但设备没到最大」。实现：`_lastAxisDragAt` + `_pendingDriveAxis` /
`_pendingDriveValue` + 140ms 的 `_limitDriveTimer`，下发统一走
`App.Engine.TryMoveCalibrationAxis(axis, value, 150)`。
